# Bank Management System

A simple Java bank account management system that supports account creation, balance checks, deposits, withdrawals, transfers, and account deletion. It ships with two interfaces built on the same core banking logic:

- A **console (CLI)** interface
- A **Swing GUI** interface

Account data is persisted to a flat text file (`database.txt`) between runs.

## Features

- Create accounts with a randomly generated, Luhn-valid 16-digit account number
- PIN-protected operations (balance check, withdrawal, deletion)
- Deposit and withdraw funds
- Transfer funds between two accounts
- Delete an account (with PIN verification)
- Transaction history tracking per account (deposits/withdrawals with timestamps)
- Simple file-based persistence, loaded on startup and saved after each operation


## Requirements

- Java Development Kit (JDK) 8 or later (uses `java.time.LocalDateTime` and standard Swing)
- No external dependencies — everything relies on the Java standard library

## Building and Running

### Compile

From the project root (with the package folders `bank/`, `database/`, `cli/`, `ui/`, `user/` in place):

```bash
javac Main.java bank/*.java database/*.java cli/*.java ui/*.java user/*.java
```

### Run — GUI mode (default)

```bash
java Main
```

This opens the Swing main window with buttons for all operations.

### Run — Console mode

```bash
java Main -console
```

This starts the interactive text menu:

```
1. Create an account
2. Check the balance
3. Deposit
4. Withdraw
5. Transfer
6. Delete account
7. Exit
```

## Data Persistence

- On startup, `AccountDatabase` reads `database.txt` from the working directory.
- The file's first line is the account count, followed by one line per account in the format:

  ```
  accNumber_accHolder_pinCode_balance
  ```

- The database is rewritten after every account-modifying operation (create, deposit, withdraw, transfer, delete).
- **Important:** `database.txt` must exist (even if empty/zero accounts) before the first run, since `AccountDatabase.load()` exits the program if the file is not found.

## Account Numbers

Account numbers are 16-digit strings generated by `AccNumber.createRandomNumber()`, starting with `4` or `5` and satisfying the Luhn checksum algorithm (the same validation scheme used by real card numbers) — this is used purely as a way to generate/validate unique-looking IDs, not for real payment processing.

## PIN Codes

- Must be exactly 4 digits (enforced at account creation in both CLI and GUI).
- Required to check balance, withdraw, and delete an account.

## Known Limitations

- `database.txt` uses a plain, unencrypted text format — not suitable for storing real financial or personal data.
- The GUI's `Deposit` and account creation flows do not always enforce PIN checks as consistently as `Withdraw` and `Remove` do.
- `Account(String info)` (the string-parsing constructor) does not actually populate the instance it's called on — it constructs a throwaway `Account` internally instead of assigning to `this`. This affects account loading from the database.
- No concurrency handling — not designed for simultaneous multi-user access.
